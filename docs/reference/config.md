Generated by `bun run docs:gen` from `apps/api/src/cli/config/schema.ts`. Do not edit.

The file `liaison config apply --config <path>` reads, in YAML or JSON. The top level is strict: an unknown section is a usage error (exit 2). Values can reference environment variables as `${VAR}`. See [the provisioning CLI](../provisioning-cli.md) for how each section is applied.

In a path, `[]` is an array entry and `<key>` a key of your choice.

## limits

Type `orgCapsSchema`, optional.

The authoritative provisioning config schema. Top level is strict. The org's caps (modules/org/caps.ts), operator only: no agent config tool takes this section. A named cap is set, `null` makes it unlimited, a cap not named is kept. A cap is a whole number of at least 1 (0 is refused) and at most its bound: the same schema as `organizations.caps` (one bounds table).

## liaisonTeam

Type `strictObject`, optional.

The two opt-ins to share with the Liaison team, instance-wide: register this server (a random id, the version, the edition and the active user count), and allow bug report forwarding (needs register). Both default to off; an answer of "no" is an answer and is recorded. Operator only.
