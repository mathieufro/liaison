# API backend (Hono + Bun)

Before writing a route, service or middleware, read an existing module for the pattern. `src/middleware/README.md` covers the middleware factory, `src/db/README.md` covers Drizzle, schema organisation, RLS and migrations, `docs/backend-overview.md` covers the architecture.

`src/`: `app.ts` (Hono assembly, mounts every module route, testable without starting the server), `index.ts` (Bun entry, boots infra), `modules/` (one per kernel component; the agent area is `modules/agent/`, split by concept: runtime, context, tools, memory, skills, routines, directory and so on), `services/` (cross-cutting orchestration, e.g. `security/`), `infra/` (events, jobs, email, websocket), `db/`, `lib/`, `middleware/`, `tests/`.

## Conventions

- Routes in `routes.ts`, extra handlers in `foo-routes.ts`. Services named for what they do (`thread.ts`, `jwt.ts`), or `service.ts` when there is one. Tests colocated. A new kernel component gets a new `modules/` directory.
- **No barrel files**: import the specific file (`~/modules/auth/jwt`). Sole exception: `src/db/schema/<app>/index.ts` re-exports every table and enum so the tree imports `~/db/schema/kernel`. Add no others.
- Hono: method chaining (`.get().post()`) preserves `hc` client inference; `createMiddleware<AppEnv>()` for typed middleware; `zValidator("json", schema)`; a named instance per route file mounted with `app.route()`.
- **Review registries take one file per change.** A new entry in the privileged-import allowlists goes in `src/tests/db-import-allowlist/<feature>.json` (`{ "privileged": { "<path under src/>": "<why>" } }`, sections connection, privileged, sql, publishEvent); a reviewed org source in `test-support/security/privileged-org-reviews/<feature>.json` (sections trustedSources, reviewedDispatch, reviewedOutsideRoutes, reviewedOrigins, reviewedRegistries); a scope read in `src/modules/apps/tool-scope-read-oracle.allowlist/<feature>.json` (an array of `[file, line, reason]`); a moved app in `src/modules/apps/moved-apps.d/<name>.json`, its move's test in a test file of its own. The literals in those files keep their entries but take no new ones: two PRs then add two files instead of two lines at the same end of one list (`test-support/registry-dir.ts`). Staleness checks apply to file entries the same.
- Drizzle query builder for all CRUD; raw SQL only for `SET LOCAL`, complex CTEs or window functions, and migration DDL. Schema imports, never string table names. `db.transaction()`, never `sql.begin()`. Types from `typeof table.$inferInsert` / `.$inferSelect`. One `pgSchema()` per app (`kernel`, `app_<name>`).

## Migrations

`0000_initial.sql` is the frozen baseline: live databases were built by applying migrations in order, so every schema change (table, column, RLS policy, trigger) is a NEW numbered forward migration, never an edit to a shipped one.

- `bun run db:generate` diffs from the schema, `bun run db:migrate` applies. Hand-author `NNNN_description.sql` for DDL the differ cannot express.
- Forward migrations must be safe against existing data: `IF NOT EXISTS`, backfill before `NOT NULL`, drop a column only once unused. Never hand-patch with a loose `ALTER TABLE`: it diverges the DB from the history and breaks the next pull and the live deploy.
- Clean slate only when you mean it: `bun run db:reset && bun run seed --yes` (dev), `bun run db:reset:test`.
- **Expand/contract (binding).** During a deploy the previous release runs on the new schema: release N's code must run on N+1's schema. Remove a column, table, enum value or jsonb key only after a release that no longer uses it; code reading an enum, `state` or jsonb shape tolerates unknown values (skip or treat as opaque, never throw). `bun run check:migration-safety` (CI, `scripts/check-migration-safety.ts`) refuses unsafe statements in migrations above `scripts/migration-safety-baseline.json` unless annotated: `-- contract: <reason>, unused since <PR or release>` (file), `-- expand-safe: <why>`, `-- reviewed-dynamic: <reason>` (DO / EXECUTE / DDL in a function body), a non-zero `SET LOCAL lock_timeout` before any `ALTER TABLE` on an existing table, and for an index build on an existing table (`CREATE INDEX`, `ADD ... PRIMARY KEY|UNIQUE`) a non-zero `SET LOCAL lock_timeout` before it plus `-- index-build: <table> <rows> <ms>` (`CONCURRENTLY` is impossible: one transaction). Rules table: `docs/backend-overview.md` "Changing the schema without downtime".
- **Migrations run once under a lease** (`runMigrations` / `withMigrationLease` in `src/db/migrate.ts`, row `drizzle.liaison_migration_lock`, created by the migrator itself, never by a numbered migration, so it works on an empty database). The image entrypoint (`apps/api/scripts/entrypoint.sh`) migrates on start unless `LIAISON_MIGRATE_ON_START=false`; `migrate` as its argument runs migrate + catalog reconcile and exits. A production start of an image older than the database's schema is refused either way (`src/db/schema-guard.ts`).
- `src/db/migrations/.baseline` plus the `check:migration-baseline` guard lock the 0000 sha256, and the lock is armed: `.baseline` carries `"prelaunch": false`. 0000 is frozen, so every schema change is a new forward migration.

## Error reporting (BINDING, see `docs/conventions.md`)

Never return a bare "Tool execution failed" or "Internal error". Every caught error surfaces the real detail (tool or operation, HTTP status, `code`, upstream `body`, offending field) to the agent or tool result, and is captured with `log.error({ err, ...context })` carrying enough context to become a field bug report. The external client still gets only the safe message: `errorHandler` sends `message`, `code`, `status`, never `body`. Canonical shape: `modules/agent/tools/tool-bridge.ts` and `modules/apps/execute-tool.ts` (a typed error's status, code and body flow through the envelope instead of flattening to `tool_error` / 500).

## Email: two channels

Swappable `EmailProvider` in `src/infra/email.ts`. Adapters: `ConsoleEmailProvider` (dev and test default; tests inject with `setEmailProvider()` and read `.sent[]`), `SmtpEmailProvider`, `ResendEmailProvider`. Without `SMTP_HOST` mail logs to console. Env: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_SECURE`, `EMAIL_FROM`.

- `getEmailProvider()` is the default channel (`RESEND_API_KEY`, else `SMTP_HOST`, else console): customer and app-facing mail not sent through a per-org connected account, such as the tickets CSAT survey.
- `getSystemEmailProvider()` is the system and auth channel (sign-in codes and magic links, 2FA step-up, password reset, invitations, attention digest). It uses `SYSTEM_RESEND_API_KEY` when set, otherwise inherits the default, so nothing silently goes real. Inject with `setSystemEmailProvider()`.
- Pick by recipient: a team member who must receive it goes system, anything customer-facing goes default or the app's connected-account path. Sends are fire-and-forget in a try/catch with `log.error`: email failure must not block the request.
- Managed edition, org-scoped mail only (invitations, digests, CSAT; not sign-in, resets or handoffs): `getOrgSenderTransport(orgId)` (`modules/org/email-from.ts`) returns the org's own verified sender and a transport on its domain-restricted key (pushed by the control plane to `PUT /api/cloud/orgs/:id/mail-sender`, stored as `settings.cloudSender`, key encrypted), else `"<Org> via Liaison" <notifications@<EMAIL_FROM host>>` with `provider: null` (the site's own channel); null outside managed, so self-hosted sends are unchanged. Tests inject the org transport with `setOrgSenderProviderFactory()`.
- Per-org `from` and `replyTo` come from `getOrgEmailConfig()` (`modules/org/email-from.ts`), falling back to `env.EMAIL_FROM`. With Resend the `from` domain must be DKIM/SPF verified or the send is rejected. `infra/email.test.ts` boots a real in-process SMTP server for round trips.

## Agent file attachments

`attachFileToParent` / `attachFilesToParent` (`modules/files/attach.ts`) is the one primitive. It copies, never moves, a `kernel.files` row the caller can read onto a registered `fileParent`, guaranteeing: source read under the caller's RLS context, type not executable per the `isBlockedFileType` extension and MIME denylist (a heuristic, not a content scan; `LIAISON_ATTACHMENT_ALLOW_EXTENSIONS` lifts it for staff-authored files only, decided from the file's origin by `isBlockedStoredFile`; inbound attachments are virus-scanned through clamd when `CLAMAV_HOST` is set, `lib/clamav.ts`), destination `writeScope` held and parent row visible, org storage quota, and idempotency via `kernel.files.copied_from_id` (partial unique index, so concurrent retries never duplicate). It emits a provenance-bearing `file:create` event into the audit timeline.

- **Destination**: declare a `fileParent` on the entity in the manifest (`tableName`, `schemaRef`, `joinOn`, `readScope`, `writeScope`), call `attachFilesToParent` from the send handler (host apps like `tickets`) or the `files_attachToParent` RPC bridge (apps whose handlers reach the host through ctx, like `mail`), and add an `attachments: string[]` tool param.
- **Source**: have the content exist as `kernel.files` rows and `files_list` discovers them for free. External connectors materialise bytes into a row (e.g. `files_importAttachment`) and return the id.
- Three outbound MIME paths: `buildRfc2822Message` in the mail handlers (`apps/mail/handlers.ts`, mail-private; its header encoding comes from `lib/email/header-encoding.ts`), the shared host encoder `toRfc2822` (`lib/email/rfc2822.ts`, used by `tickets`, RFC 2231-encodes non-ASCII filenames), and SMTP where nodemailer owns encoding.
- A gated send's approval summary lists each attachment's filename and origin (`buildAttachmentSummaryLines`), flagging any file pulled from a different conversation or ticket than the one being replied to.

## Scaling constraint

A process has one role, `LIAISON_ROLE` (`lib/process-role.ts`): `all` (default: API, BullMQ workers and singletons in one container), `api` (HTTP + WebSocket, no workers, never leader) or `worker` (workers and singletons behind a health-only server; `/healthz` + `/readyz`). `/readyz` (`lib/readiness.ts`) is 200 once the role's boot is done and 503 while draining.

- **Jobs gate (per node):** BullMQ workers in every `all`/`worker` process follow the Patroni probe (`SINGLETON_LEADER_URL`; unset = open), never the lease, so several worker processes run jobs at once.
- **Singletons (per cell):** anything that must run once (outbox drain, legacy queue move, node-lease sweep, demo loops) registers `registerSingleton({ name, onAcquired, onLost })` in `infra/leadership.ts`, never boot code or a bare `setInterval`. They run only while `isLeader()`: lease-eligible role AND the Redis leader lease (`infra/leader-lease.ts`, `LEADER_LEASE_TTL_MS`/`RENEW_MS`/`POLL_MS`, 15 s/5 s/1 s) AND Patroni leader. `isLeader()` fails closed. On loss, `onLost` hooks are awaited before the lease is released; a Patroni replica never contends for the lease.
- **Org setup is on demand:** each process fills its in-memory app registries per org on first touch through `awaitOrgApps` (`modules/apps/init.ts`): requests, MCP, WebSocket upgrades, job dispatch, outbox, state materializer, reindex and inbound webhooks for an existing org. Boot registers no org (start time is flat in the org count); event `once` dispatch and the OAuth callback ensure too, and an org-scoped registry miss for an org not set up throws outside production (`modules/apps/org-registry-guard.ts`). Persistent setup writes are skipped while the org's setup stamp (`modules/apps/setup-stamp.ts`: `LIAISON_VERSION`, active app versions, Google sign-in config, app error state) matches; writes take the `org-setup` advisory lock and re-check. With `LIAISON_VERSION=dev` every process start re-runs setup once per org.
- **Two releases overlap (rolling deploy):** `deploy/rolling-deploy.sh` runs the new `api`/`worker` beside the old ones on one install root until the old ones drain (up to 10 min), so release N must run beside N+1. A version dir (`<installRoot>/<name>/<version>/`) is written once, through a `.tmp-` dir and a rename, and never rewritten (`modules/apps/version-dir.ts`; different files under an installed version are refused). A process never lowers `apps_active_version`: a reconcile whose catalog is older than the active version skips and logs `app_version_ahead`, and that process runs its own catalog version (`versionForThisRelease`, `modules/apps/catalog.ts`) when a release's catalog installed the active one (`source_url` `catalog:`); an uploaded version is the one every process runs. The same rule applies when a process follows another's activation (`syncActiveVersionsFromDb`, `readInstalledAppDescriptor`). A prune keeps every version a live process announces (`modules/apps/versions-in-use.ts`, one Redis hash, liveness from the instance registry; unreadable = prune nothing). The `migrate` one-shot reconciles the catalog `--strict` (non-zero when an app fails, so the deploy stops); `check:bundled-app-version` makes a changed bundled app raise its version. The additive-schema check reads the running version's schema from `apps_installed.manifest_schema` when its files are gone.
- **Live state (per instance, in Redis):** sockets, presence, mail access and the agent stream cap are instance-scoped Redis entries (`infra/websocket-state/redis.ts`, `modules/agent/stream-slots.ts`); the local socket table stays the only source for local delivery. Every process (every role) writes a heartbeat record (`infra/instance-registry.ts`, `LIVE_INSTANCE_TTL_MS`/`HEARTBEAT_MS`, 30 s/10 s); readers ignore entries whose instance has no record. The leader sweep (`LIVE_SWEEP_INTERVAL_MS`, 10 s) runs the `onDeadInstance(name, fn)` hooks; `onInstanceRecovered(name, fn)` rewrites a process's own entries after its record lapsed. New instance-scoped state registers both hooks. Every Redis await is bounded and each read has a fixed failure direction: mail access closed, mailbox unlock locked, stream cap open, online/offline from local sockets.
- **Event delivery:** every bus handler declares `delivery` (`onEvent(fn, { delivery, name })`, `subscribeToEvent(..., { delivery })`, `infra/events/event-bus.ts`). `once` runs only in the publishing process and skips peers' remote copies; for a durable event that process is the outbox leader. Anything that writes (rows, jobs, outside calls) is `once`. `per-replica` runs in every process (caches, this process's sockets); a per-replica `onEvent` handler holds one pattern subscription on all events channels, so the process receives every event and filters locally (deduped by `_msgId`).
- **Event routines:** subscribed in every process. A change announces the routine id after its transaction commits (`announceEventRoutineChange`, `infra/jobs/event-routine-subscriber.ts`); every process re-reads the row, and resyncs from the table on subscriber reconnect, on leader takeover and every 60 s (that pass compares one fingerprint of the table and resyncs only when it moved). One bus handler per event type routes an event to the routines of its org.
- **Live agent turns (cell-wide, in Redis):** every `agent_stream` frame is recorded in the turn's Redis Stream (`modules/agent/runtime/stream-registry.ts`) by one Lua script that allocates its `seq` and item id (`r<n>` / `t<n>` / tool call id), so two producers of one turn agree. Frames on the wire carry `seq` + `itemId`; `GET /api/agent/stream-state/:threadId` serves the folded snapshot with its `seq`, and the client follows frames above it (snapshot + tail). A checkpoint every 500 frames folds the stream and `XTRIM MINID`s what it covers; a finished turn stays readable `AGENT_TURN_STREAM_TTL_S` (600 s). Turns of a dead instance are dropped by readers and the sweep (no terminal message; resuming is P3). Superseded-turn waits and sub-run cancels work across processes.
- **Live runs (taint) and credits:** `modules/agent/scopes/live-runs.ts` counts runs per thread cell-wide (instance-scoped ZSET, fails closed), so a new turn clears the taint mark only when no other run is live anywhere. Credit balance updates go through `broadcastEphemeral`, so every process fans them out.
- **Mailbox decrypt routing:** a pending request lives in the minting process. An answer that lands elsewhere is forwarded over an HMAC-signed HTTP call (key HKDF'd from `JWT_SECRET`, 30 s skew, replay set) to that process's internal listener (`modules/agent/mailbox-plaintext/mailbox-forward.ts`, `LIAISON_INTERNAL_PORT`/`HOST`/`BIND`, bound to the advertised address by default, capped 1 MiB over the public answer route's `MAILBOX_ANSWER_BODY_MAX_BYTES`, signature checked over the raw body before any parse, URL in the heartbeat record). Decrypted mail never touches Redis. Unreachable owner = 409 `WRONG_INSTANCE`. **Who may answer (security note):** the mailbox's end-to-end encryption exists so that an admin or a coworker can never read another member's mail, not to stop a user's own devices from serving that user's own agent. So any of the user's unlocked apps answers for the user's own agent's requests, silently: the request (`mailbox_decrypt_request` / `mailbox_search_request`) goes to the requester's own connections only (`MAILBOX_REQUEST_ACTIONS` in `infra/websocket.ts`), and carries the turn's nonce and a per-request `answerToken` (an opaque random id, not key material). The registry accepts an answer only from an authenticated session of the same user and org with the nonce (the window that started the turn) or the token (any other app of the user); anyone else gets 404, a late duplicate 200 `alreadyAnswered`, and the forward hop carries user, org, nonce and token. A usable answer settles at once; a locked or empty one settles only once every unlocked connection of the user has answered or none is unlocked (`getMailboxAnswerers`), or at the deadline. `mail.convert` accepts the nonce only: the consent stays the owner's, in the window they asked in.
- **Retried writes:** `withIdempotency` (`lib/idempotency.ts`) dedups a write across processes by key in Redis (pending NX 60 s, done 24 h, other payload 422, Redis down = open). The message post uses it keyed by `correlationId`.
- **Client recovery:** the web client (and the desktop and phone shells around it) notices a dead socket within ~9 s (5 s ping, 4 s pong deadline, probes on online/focus/visibility/foreground/wake; `apps/web/src/primitives/createWebSocket.ts`), reconnects with a jittered backoff and resyncs every open view after a real reconnect (`framework/resync.ts`); reads time out at 20 s and retry, a lost send is re-sent once with its `correlationId`. So several processes may serve the API behind a load balancer, with no sticky sessions. A turn whose process dies or drains past its budget is resumed by another process from its last complete step: the turn record and journal (`runtime/turn-ledger.ts`, `runtime/turn-journal.ts`), the handoff at a step boundary (`runtime/turn-handoff.ts`), the claim, actor re-check and resume (`runtime/turn-resume.ts`), and write tool calls keyed `tool:<turn>:<tool>:<argsHash>:<n>` in the effect ledger (`runtime/tool-effect-key.ts`, `lib/effect-once.ts`). A thread view follows a resumed turn over the socket (the `resume` frame rewinds the cut step, `apps/web/src/modules/threads/message-store.ts`); a `/chat` SSE caller gets a `restart` frame naming the turn and re-attaches with `GET /api/agent/turns/:turnId/events` (requester only, in a thread they can read; `modules/agent/routes.ts`).
